WORKFORCE: WIFI BUILD + START ON ANY NETWORK
=============================================

Do not use this command for the normal workflow:

  docker compose up -d --build

It combines the internet-dependent image build with app startup.

FIRST TIME, OR AFTER CHANGING CODE
---------------------------------

1. Connect the PC to Wi-Fi/internet.
2. Open PowerShell in the project folder.
3. Run:

   .\BUILD-ON-WIFI.ps1

4. Run the app now, or switch to the factory database network first if live
   workforce data is needed.
5. Run:

   .\START-WORKFORCE.ps1

NORMAL START, WHEN THE IMAGES ARE ALREADY BUILT
-----------------------------------------------

Run this on Wi-Fi, the database network, or without a network:

  .\START-WORKFORCE.ps1

Equivalent command:

  docker compose up -d --no-build --pull never

CHECKS
------

Server/Nginx liveness:

  curl.exe http://localhost:5056/api/live

The interface starts without PostgreSQL. Database-backed pages can only load
live workforce data while PostgreSQL is reachable.

PostgreSQL and workforce table:

  curl.exe http://localhost:5056/api/health

Expected full health response:

  {"ok":true,"db":"connected","workforceupdate":"ready"}

The local runtime image names are:

  4thproject-workforce-app:local
  4thproject-workforce-nginx:local

Compose is configured with pull_policy: never, so normal startup will not
contact Docker Hub. Internet is needed only when rebuilding dependencies or
pulling newer base images.

Nginx waits only for the backend container to start. It does not wait for a
PostgreSQL connection or for the backend health-check interval.
